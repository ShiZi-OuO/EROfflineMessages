# 正常客户端样本采集：首轮可行性验证

用户于 2026-10-24 取消后续一小时稳定性测试，要求优先获取服务器来源的真实玩家谏言。之前选择的“先只用构造数据”不再限制接下来的正常客户端取样；它不自动授权联网注入、内存修改、非标准请求或反作弊配置变更。

## 当前采用的流程

1. 正常退出离线回放游戏。保留独立构造包，不替换其数据。
2. 从 Steam 原版入口启动。已检查本游戏 Steam LaunchOptions 为空，游戏根目录无常见代理注入 DLL。原版 EAC 保持启用；不向该进程附加观察器、不读写它的内存、不加载回放 DLL。
3. 由游戏正常登录、收取谏言。先在已知地点阅读两三条，记录其中一条的完整原版文字、评价与地点。正常客户端请求由游戏发出，没有独立协议客户端或跨区域自动请求。
4. 正常退出官方客户端。待保护进程正常退出后，使用空 ME3 脱机配置，不加载任何 replay/observer DLL，继续同一原版角色。
5. 仅在已验证脱机、精确 EXE、EAC 不存在时，外部工具以 QUERY_INFORMATION / VM_READ 读取缓存中的允许字段。既不打开存档文件，也不写游戏内存。
6. 与采集前的匿名排除基线比较，删除所有构造记录，排除原有语义及仅评价变化的记录。剩余数据先存为 `unverified_client_cache_candidates`，不生成可安装的官方数据包，不将候选数量记为已验证官方样本。
7. 对照先前在线阅读界面的文字、评价、地图及位置。只有来源和结构得到实际核对后才提升为有限官方客户端接收样本，再在离线回放中复验。

关键未知：本作会不会在正常退出和脱机重启后保留足够完整的在线接收缓存。曾观察到的跨进程旧缓存不能单独证明本轮新数据会保留。若差分为空，先调查缓存寿命和序列化路径；不会因此擅自切换联网注入或直接服务器请求。

## 采集前状态记录（历史）

- 稳定性监测已取消，部分时段数据不是一小时通过。
- 首次直接官方启动器尝试遇到 30005 / EAC unload timeout。用户正常关闭后，检测 EAC 服务已自然停止；随后通过 Steam 原版入口启动，检测到 eldenring 与 EAC 进程。没有更改服务、驱动、安全软件或反作弊配置。
- `tools/capture_client_cache.py` 已实现；四项离线对照测试通过。采集前排除基线有 15 条非构造记录，这些历史来源不确定，不能当成新收录的官方样本。
- 候选文件仅写入不随发布包复制的 `build/capture/`。输出只含地图、区域、坐标、朝向、原版句式词语编号和评价。候选键由语义摘要生成；不导出原始服务器键、账号、玩家姓名、外观或凭据。
- 此流程仍需实际完成在线接收、重启后读取及界面对照。目前验证过的新增官方样本为零。

## 离线工具命令

在无 DLL 的脱机游戏已载入同一角色后：

```text
python tools/capture_client_cache.py --baseline build/capture/pre-online-baseline.json --output build/capture/after-online-candidates.json
python tests/client_cache.py
```

基线不能由新安装者复用本机历史数据；应在自己的首轮正常联网前，通过相同工具创建排除基线。`--import-baseline` 仅用于导入本工程已有的离线观察记录作为排除集合，不代表确认其中记录的来源。

公开结构和协议研究只作为字段线索：[fromsoftware-rs 固定修订](https://github.com/vswarte/fromsoftware-rs/blob/6da5f80ae561944f45470e353be996a05137095a/crates/eldenring/src/cs/net_man.rs)、[waygate-server 固定修订](https://github.com/vswarte/waygate-server/blob/197ef607eccb912299d773df7c23ae0268164ab2/message/src/eldenring/bloodmessage.rs)。这些参考不证明官方服务允许任意调用，也没有用于发送请求。

## 联网登录对照结果（按执行时序记录）

首次 Steam 原版启动后持续出现普通“无法登录游戏服务器”提示，没有出现不当行为或联机处罚提示。只读网络元数据显示游戏连接本机 FlClash 7890 端口；当时系统代理开启、规则模式运行。不能据此直接判断官方服务宕机。

用户明确批准仅为 eldenring.exe 添加临时 DIRECT 规则。修改前已在不随包发布的 build/network-diagnostics/private-backup-* 保存原配置和摘要；通过 FlClash 当前选中配置的“扩展→标准→附加规则”添加 PROCESS-NAME / eldenring.exe / DIRECT。数据库已确认只有这条目标进程的新增规则，未禁用；未修改全局模式、系统代理、虚拟网卡、其他策略组或反作弊设置。

原版游戏点击“确定”重试后进入服务器公告，标题画面明确显示“联机模式”、App 1.17.2 / Regulation 1.17.3，截图 official-client-online-title.png。随后正常继续近林洞窟角色。此项证明登录成功，不等于谏言样本已取得；仍等待首批阅读与离线缓存对照。临时规则在采集结束后需按原范围还原，不能覆盖期间用户其他设置变动。

## 首轮正常退出后的提取结果

原版在线阅读“前有集团”、总评价 7 已截图。正常退出后，等待 EAC 服务自然停止，再由空 ME3 脱机配置继续同一角色；标题脱机模式已取证。该进程只有 ME3 host，没有观察或回放 DLL。外部只读校验的 online=0、menu online=0、原生地图为 m31_03_00_00。

与原有 15 条匿名排除基线比较，发现 103 条新语义候选：近林洞窟地图 41 条，m60_42_37_00 开放世界区块 62 条。它们来自本轮正常客户端缓存差分，不代表服务器全量，也不证明两图每个记录都已逐条核对。

其中只有一条匹配原版模板 10000、词语 30008（group / 集团）、无第二句，good=4、poor=3、显示总数 7；区域 3103001，区块坐标 (-64.2692108,110.2405396,-3.5924406)，位于在线截图对应的近林洞窟赐福旁。已创建仅含这一条的 official-pilot-1 语义包，匿名本地键使用 7d 命名空间，不导出原始服务器消息键或身份字段。该条的在线文字/评价与离线结构对应已经核实；离线回放显示仍待验证。

无 Mod 的脱机对照里只有两个较远的原版脚本显示实例，没有赐福旁的对应显示实例。因此缓存记录存在不等于原版脱机会自动显示，仍需本工程的原生回放流程。
